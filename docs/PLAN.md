## Этап 9. Тренировка и адаптация весов — БО 3, 4, 6, 2

Ключевой этап: он реализует диаграмму последовательности (рис. 1.9) и схему алгоритма для листа 5.2.

**Промпт:**

(2) WorkoutSet.volume(), Workout.calcTonnage() без импорта services, Workout.create в транзакции. (3) RecordDetector.detect по спецификации. (4) WeightAdaptationService по спецификации. Тесты: формулы StrengthMetrics (80 кг × 8 → Эпли 101,3; Бжицки 99,3); сценарные тесты adapt(workout) на каждую ветку решения и округление по инвентарю; detect(workout) с моком findBest. Всё — через публичные методы с mock.method.

**Спецификация WeightAdaptationService.adapt(workout)** — для каждого упражнения, где внесены все рабочие подходы:
1. `#evaluateSets(sets, repsMin, repsMax)` → `ABOVE` (все подходы ≥ repsMax), `WITHIN`, `BELOW` (хотя бы один < repsMin).
2. `#decide(result, history)`, где history = `WorkoutSet.findHistory(peId, failLimit)`: ABOVE → INCREASE; BELOW в `#failLimit` (=2) тренировках подряд → DECREASE; иначе KEEP.
3. `#calcStep(exercise, weight)`: INCREASE — `max(exercise.weightStep, weight × 0.02)`, но не больше `weight × #maxIncreasePct` (ACSM 2–10 %); DECREASE — `weight × 0.10`.
4. `#roundToEquipment(weight, equipment)`: штанга — кратно 2,5; гантели — 1; тренажёр — 5; собственный вес — 0 (вес не меняется, растут повторения).
5. Проверка по 1ПМ: новый вес не выше `1ПМ × верхняя граница интенсивности цели` из таблицы 1.1.
6. `ProgramExercise.updateWeight()` + `WeightHistory.create()` с decision → результат в массив.

**Спецификация RecordDetector.detect(workout)**: по каждому упражнению считает максимальный вес, максимум повторений, максимальный расчётный 1ПМ (Эпли), тоннаж упражнения; сравнивает с `PersonalRecord.findBest` через `#isBetter`; новые рекорды сохраняет.

**Для записки:** схема алгоритма адаптации (лист 5.2 и приложение Б), листинг `WeightAdaptationService` и `StrengthMetrics` (приложение «листинг алгоритмов»), скриншот результата сохранения тренировки с пояснением решения.
